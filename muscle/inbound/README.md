# muscle/inbound/ — Real-contract staging area

Real, deployed mainnet contracts land here before they become permanent Schlieren
regression tests. Real compiler-generated bytecode has patterns — ABI dispatch via
function-selector jump tables, the free-memory-pointer convention at `0x40`,
`Error(string)`/`Panic(uint256)` revert encoding, packed storage layouts — that
hand-written test bytecode doesn't reproduce. Running the actual interpreter
against actual deployed code is a different (and often better) bug-finding lever
than synthetic probes.

## Layout

```
muscle/inbound/
  manifest.json          — index of every staged contract + status
  README.md              — this file
  <Name>/
    runtime.hex           — deployed runtime bytecode (0x-prefixed), from eth_getCode
    meta.json             — address, fetch block, byte length, known function
                             selectors, and free-text notes on why this contract
                             is interesting / what it stresses
```

## Lifecycle

1. **staged** — bytecode fetched and dropped in via `tools/import_real_contract.py`
   (or, for a specific real transaction against it, `tools/import_real_tx.py`).
   Nothing has run yet.
2. **promoted** — a real call against the contract has been run through Schlieren
   and turned into a permanent test (`Schlieren.Tests/Regression/…`), with the
   expected outcome pinned either to a real mainnet receipt (`import_real_tx.py`
   captures `status`/`gasUsed`/`logCount` as ground truth) or to a hand-verified
   behavioral invariant of the real source (e.g. "WETH9.deposit() must increase
   balanceOf[sender] by exactly msg.value").
3. **rejected** — tried, not useful (e.g. bytecode turned out to be a proxy with
   no interesting logic of its own, or requires prestate too complex to
   reconstruct without prestateTracer access).

Update a contract's `status` in `manifest.json` when it moves stage.

## Tools

```bash
# Stage a contract by address — fetches runtime bytecode, writes meta.json,
# updates manifest.json.
python tools/import_real_contract.py <address> <Name> [--note "why this one"]

# Reconstruct a full replayable fixture for one real, already-settled
# transaction — sender/target balance+nonce+code at the parent block, block
# context, calldata, and the REAL receipt (status/gasUsed/logCount) as ground
# truth to diff a Schlieren replay against. Writes muscle/real_tx/<hash>.json.
python tools/import_real_tx.py <tx_hash> [--storage-slots ADDR:0xslot,...]
```

Both use free public RPC endpoints (`eth_getCode`/`eth_getTransactionByHash`/etc.)
— no `debug_traceTransaction`/prestateTracer, since free public nodes don't expose
the debug namespace. That means `import_real_tx.py`'s prestate reconstruction is
best-effort: it fetches balance/nonce/code for the sender, the target, and any
address that emitted a log, but storage for slots not explicitly passed via
`--storage-slots` is reconstructed as empty. For contracts where correctness only
depends on freshly-written slots (a fresh `deposit()` into an empty balance
mapping, for instance) this doesn't matter; for anything reading pre-existing
storage it does — pin the specific slots you need, or accept that only
success/gasUsed/logCount are reliable ground truth for that fixture, not full
state-root equivalence.
