# Schlieren Gas Rule Inventory

## Method and Scope

Exhaustive read of every `.cs` file under `Schlieren.Core/` that contains gas-affecting logic, followed by three independent read-only audits split across opcode/storage, CALL/CREATE/SELFDESTRUCT, and precompile paths. Each protocol row records the exact current formula, all inputs, fork-dependent behavior, source path with 1-based line number, existing tests, and findings. Because the product goal is accurate Case Inspector diagnosis, the non-charging gas-tree and diagnosis formulas are audited separately near the end of this document. No external EVM client or runtime comparison tool was used. No production code was modified.

Search strategy: overlapping keyword sets (`Gas`, `ConsumeGas`, `RefundGas`, `GasUsed`, `GasLimit`, `Stipend`, `Warm`, `Cold`, numeric literals ≥100) across all production source, followed by manual verification of every candidate.

Excluded from the **protocol charging count**, but audited under `Diagnostic Gas Attribution and Root-Cause Rules`:
- `DivergenceDiagnostics.cs`, `StructuralPatternRules.cs`: diagnostic formulas, never executed during gas charging.
- `GasTree.cs` and `StateTransition.ApplyTransactionWithGasTreeAsync`: reporting/diagnostic execution paths whose arithmetic can change the explanation even when canonical execution is correct.
- `NodeConfiguration.cs`, `ConfigurationLoader.cs`: RPC gas caps, not protocol rules.
- `ExecutionTrace.cs`, `MismatchContext.cs`: tracing/reporting only.

## Uncovered or Ambiguous Paths

- EIP-211 return-data clearing/replacement and bounded output-copy state is spread across every CALL/CREATE early-exit path. It is not a charge itself, but can change later RETURNDATA execution and must be journaled for exact diagnosis.
- SELFDESTRUCT balance transfer, self-beneficiary burn, EIP-6780 deletion restriction, and frame termination are outside the four gas rows. They affect state mismatches and later same-transaction behavior; the source comment says Shanghai although the implemented fork gate is correctly Cancun.
- Actual value movement for CALL, CREATE, top-level transactions, and direct precompiles is not a gas movement, but Case Inspector must separate it from fee residuals before dividing balances into gas units.
- Exceptional early exits (static violation, stack underflow, absent subcall handler, memory/charge OOG, call depth) currently collapse into generic halt output; exact root-cause diagnosis needs the failing validation rule ID and operands.
- Host limits—16 MiB EVM memory, pre-Osaka ModExp 8192-byte lengths, ModExp 10-billion gas saturation, and fork-backed `Unknown` storage emptiness—are protocol-visible but are not represented as named schedule policies.
- Existing account checks are inconsistent: CALL legacy logic, EIP-7702 refund logic, and some SELFDESTRUCT branches infer existence from nonce/balance/code instead of using an existence/dead-account rule with the correct fork semantics.

## Recommended Migration Slices

1. **Typed schedule and activation first.** Define all constants, formulas, feature activation, refund rules, host policies, and initial warm-set rules in immutable per-fork overlays. Make opcode/precompile dispatch consult it.
2. **One canonical transaction evaluator.** Remove the diagnostic transaction reimplementation. Canonical execution should optionally emit a typed gas journal; Case Inspector consumes the journal without re-executing different rules.
3. **Journal exact movements and branches.** Emit `Charge`, `TransferOut`, `TransferIn`, `Return`, `RefundCounterDelta`, `Burn`, `Settlement`, and `ValidationFailure` events carrying `GasRuleId`, fork, operands, branch outcome, frame, and source boundary.
4. **Repair high-risk protocol paths.** Prioritize opcode activation, CREATE rollback/memory/deposit forks, pre-EIP-150 overflow/forwarding, initial warmth/EIP-3651, BALANCE repricing, authorization refund/existence, ModExp host clamps, and pre-London SELFDESTRUCT refund.
5. **Generate diagnosis from schedule metadata.** Replace flat constant and folder heuristics with counterfactual evaluation: compare expected versus actual journal components, compute candidate deltas under valid branches for the active fork, and rank only candidates that explain the full mismatch ledger.
6. **Add formula and conservation vectors.** Test every fork transition plus boundary values, and require `initial allocation + transfer-in = charges + burns + transfer-out − returns` per frame and exact transaction settlement reconciliation.
